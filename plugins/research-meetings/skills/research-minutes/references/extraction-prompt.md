# 抽取 agent 的提示詞

交給**一個** agent 完整讀完逐字稿。替換 `<…>` 後使用。抽取稿含逐字摘錄，輸出到暫存目錄，不進 repo。

---

你要把一場研究會議的逐字稿整理成「可溯源的素材抽取」，供記錄者據以撰寫會議紀錄。**你不寫會議紀錄本身**，只做忠實抽取，每一點都附出處。

## 檔案
- 逐字稿（已依術語表校對）：<校對版 .srt 的絕對路徑>（<N> 個 cue，約 <M> 分鐘，**請完整讀完**，可分段讀）
- 背景（只用來核對人名與術語）：<README、context.json、會中討論的程式碼或簡報>
- 輸出：<暫存目錄>/extraction.md

## 會議背景
<日期、參與者與各自角色、會議目的。註明轉錄的講者標籤可能把不同人併在一起，也可能把同一人拆開，不可直接當作身分。>

## 抽取紀律
1. **只抽會中真的說了的事。** 每一點都附：cue 編號（可為範圍）、起始時間碼、講者標籤、一句定位用的短引文（≤25 字，逐字照抄逐字稿，含錯字照抄）。
2. **語氣強度照原話。** 個別發言不得寫成共識，建議不得寫成決議，條件句不得寫成確定句。
3. **講者歸屬要有證據**（自我介紹、被點名、角色上只可能是某人），寫出依據；證據不足寫角色或只寫標籤。另整理講者標籤對照表（最可能是誰、依據、信心高／中／低），並指出標籤混雜的段落。
4. **聽不清的字不要補成通順中文。** 標「（不清）」並附原字；「疑為 X」一律標明是推測。
5. **數字、參數、文獻**逐一列出，附 cue 與原話。
6. **只抽不評。** 不寫自己對方法的意見，不寫「討論熱烈」「大家同意」。

## 輸出結構
1. 時間軸：切成 6–12 段，每段時間範圍、cue 範圍、主題、主要講者。
2. 出席線索與講者標籤對照表。
3. 報告內容（背景、目的、設計、測量、分析、目前結果），每點附出處。
4. 討論議題：每題一節，提出 → 說明 → 結論狀態，狀態只用「有明確結論」「有人建議、未定案」「未討論出結論」三者之一。
5. 待辦：要做什麼、誰做（明講才寫人，否則「未指定」）、期限（明講才寫）、出處。條件句或邀請（「有興趣的話我可以…」）另列，不當待辦。
6. 數字與參數表。
7. 不該進正式紀錄的內容（只列位置與類別）：寒暄閒談、對不在場者的評價、對機構或審查的推測、私人事務。
8. 沒把握的地方：cue 與原因。

寫完後用 script 驗證：每段引文逐字出現在所引的 cue 範圍內、時間碼與講者標籤和逐字稿一致、引文 ≤25 字。

最後在回覆中只給：時間軸摘要、講者對照結論、議題數與待辦數、最沒把握的三處。不要在回覆中貼大段逐字稿。
